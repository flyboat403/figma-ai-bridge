> 整理时间：2026-10-11 · 环境：Windows + Figma 桌面版 + WorkBuddy
> 本手册由 WorkBuddy AI 根据全程实测整理，可直接作为教学材料使用

## 一、一页速览（先看这）

**目标**：让 AI 直接读取和修改 Figma 设计稿。

**最终方案**：开源插件桥 `cursor-talk-to-figma-mcp`（本地中继 + Figma 插件）。
**不需要 Dev Mode、不需要付费计划。**

**已验证能力**（2026-10-11 实测）：
- 读：文档结构 / 页面 / 图层 / 文字 / 位置尺寸颜色
- 改：文字（读数 0.000 → 2.000 ✅）、颜色（旋钮红点 → 蓝点 ✅）
- 看：把画板导出成图片，AI 和人一起"看得见"

**日常三步**：
1. 启动桥接（未运行时双击 `启动桥接.vbs`）
2. Figma 里运行插件 → 面板显示 Connected → **面板保持开着**
3. 把频道号发给 AI，然后说需求

## 二、起点：文章①「方案二」撞上 Dev Mode 门槛

1. 老川发来掘金文章《Figma MCP 使用指南与配置教程》（https://juejin.cn/post/7572390974458953728），要求执行**方案二（Desktop Server）**，并授权代装 Figma 桌面版。
2. 执行：下载安装 Figma 桌面版 126.10.7（静默安装，签名校验通过，SHA256 与 winget 官方清单一致）。
3. 卡点：按 `Shift+D` 想进 Dev Mode 时，弹出 **"Upgrade to work in dev mode"**。
4. 查证结论：**Figma 官方 MCP 桌面服务器要求付费计划的 Dev/Full 席位**，免费 Starter 版连 Dev Mode 都没有——这是官方限制，不是操作问题。
5. 相关事实（2026-10 官方文档）：
   - 官方远程 MCP 服务器（mcp.figma.com）：所有计划可用，但 Starter 限额极低（约 20 次/月），且只允许"名单内客户端"连接。
   - 教育版（师生可免费申请）≈ Professional 级：含 Dev Mode + 约 200 次/天 MCP 配额。
6. 结论：官方路线对「免付费 + 教学铺开」不通 → 需要另找一条路。

## 三、转机：文章② 插件桥（真正能改稿的路线）

1. 老川发来文章②《让 AI 直接画 Figma 设计稿！CodeBuddy + Figma MCP 全链路实战》（https://juejin.cn/post/7621026569348513802），问"所谓的插件桥是这个吗"。核对确认：**插件桥 = 开源项目 `cursor-talk-to-figma-mcp`**。
2. 架构（三层）：

```
AI 客户端 ──(stdio/MCP)──> MCP 服务 ──(WebSocket :3055)──> Figma 插件 ──(Plugin API)──> 画布
                本机进程                      本地中继                     Figma 内部
```

3. 为什么它能改稿：走的是 **Figma Plugin API**（插件天生拥有设计文件的读写权限），绕开了官方 MCP 的 Dev Mode 开关。
4. 关键认知：**访问令牌（REST API）是只读的，改不了稿**；agent 真正改稿只能走插件桥。
5. 代价与局限：非官方方案；需要本机常驻一个中继服务；依赖 Figma 插件面板保持运行。

## 四、搭建过程（Windows 全步骤 + 全部踩坑）

### 4.1 环境：Bun
- npm 全局安装 Bun 会失败（`@oven/bun-windows-x64` 平台包被静默跳过，官方源/镜像都试过）。
- 解法：从 npmmirror 下载二进制包直装 → `C:\Users\fly04\.bun\bin\bun.exe`（1.4.3），并把 `bun` / `bunx` 垫片写入 `%APPDATA%\npm\`。

### 4.2 桥接仓库
- 位置：`C:\Users\fly04\.workbuddy-ai\tools\figma-bridge\repo\`（github: grab/cursor-talk-to-figma-mcp，main @ v0.3.5）。
- 依赖：`bun install --production`。
- 注意：**npm 包不含中继服务**，必须运行仓库里的 `src/socket.ts`。

### 4.3 启动中继
- 命令：`bun run src/socket.ts` → 监听 `ws://localhost:3055`。
- 一键脚本：`启动桥接.vbs`（后台启动）/ `停止桥接.bat`（停止）。
- 自检：`netstat -ano | findstr 3055` 应看到 LISTENING。

### 4.4 Figma 插件
- 方式 A（社区版）：Figma 社区搜索 "Cursor Talk To Figma MCP" 安装。
- 方式 B（本地开发版，推荐）：
  1. 菜单 Figma → Plugins → Development → **Import plugin from manifest…**
  2. 选择：`C:\Users\fly04\.workbuddy-ai\tools\figma-bridge\repo\src\cursor_mcp_plugin\manifest.json`
  3. 之后每次运行：Plugins → Development → **Cursor MCP Plugin** → Connect
- 面板显示 `Connected to server in channel: xxxxxxxx`——这 8 位编号就是**频道号（Channel ID）**。

### 4.5 AI 侧调用
- MCP 服务：`bun x cursor-talk-to-figma-mcp@latest`（stdio 协议）。
- 调用流程：`join_channel(频道号)` → 调用各种工具 → 结束。
- 共 **44 个工具**：读文档 / 读图层 / 扫文字 / 扫类型 / 改文字 / 改颜色 / 移动 / 缩放 / 建组件 / 导出图片……
- 本机工具脚本（`figma-bridge\` 目录）：
  - `figma_e2e_check.py <频道>`：端到端自检（加入频道 + 读文档信息）
  - `figma_call.py <频道> <工具名> '[参数JSON]'`：单次调用任意工具
  - `figma_call.py <频道> --batch '[…]'`：批量调用；导出图片自动保存 `_export_*.png`

## 五、稳定性战役（踩坑大全·血泪实测版）

这是全过程中最费劲的部分，每一条都是真实踩出来的：

| # | 现象 | 根因 | 解决 |
|---|------|------|------|
| 1 | 插件连上后约 2 分钟必断 | **Bun 运行时会掐断空闲 120 秒的 WebSocket** | 中继源码加 `idleTimeout: 0` 并重启 |
| 2 | 面板显示 Connected，但命令发不到 Figma | ① 连接其实早已断，面板文字是**过期残留**；② 等 AI 操作时窗口期已过 | 以中继日志为准（join/close 行 + netstat）；部署"自动狙击"秒级接应 |
| 3 | 连接只活了几秒就断（实测 4 秒） | **close code 1001 = "正在离开"**：面板被关闭/切走（已排查：插件代码无自杀逻辑） | ★ **面板必须一直开着**——关面板=拔电话线，谁也救不回 |
| 4 | 每次重开插件频道号都变 | 插件每次启动随机生成频道名 | 正常现象；重开后把新频道号发给 AI 即可 |
| 5 | 读图层读不到矢量图形 | MCP 服务端会**过滤掉 VECTOR 节点** | 改用 `scan_nodes_by_types` 扫类型（拿到全部 27 个图层） |
| 6 | 文字扫描（scan_text_nodes）超时 | 分块扫描与后台轮询互相干扰 | 操作前先停后台轮询进程 |
| 7 | 出现"幽灵进程" | `bun x` 实际以 node.exe 运行；父进程死后子进程不退出 | 需要时手动清理 |
| 8 | 首次 join 报"连接未就绪" | 启动竞态 | 等连接稳定 + join 重试（工具已内置） |

## 六、最终稳定形态（2026-10-11 完成）

- **自动狙击系统**：监听中继日志 → 插件一上线 **1 秒发现** → 探测器 **8 秒内自动读取**文档信息，写入 `_probe_hits.log`。
- **标准闭环**（已实测两次）：用户点单 → AI 执行 → 导出图片验收
  - 读数 0.000 → **2.000** ✅（节点 2:7）
  - 旋钮红点 → **蓝点 #1E90FF** ✅（节点 2:9）
- 中继日志具备完整取证：精确时间戳 / 断连代码 / 30 秒心跳 / 存活信标。

## 七、日常使用 SOP（三步）

1. **启动桥接**（未运行时双击 `启动桥接.vbs`；或让 AI 启动）。
2. **Figma 里运行插件**：Plugins → Development → Cursor MCP Plugin → Connect。
   ★★ 面板保持开着：不要按 Esc、不要关面板、不要切换插件。
3. **把频道号发给 AI，直接说需求**，例如：
   - "读一下这个文件的图层结构"
   - "把读数改成 220.5"
   - "把 10A 标签改成 20A，换成紫色"
4. AI 改完会**导出图片给你验收**（改了什么一目了然）。

## 八、教学复用建议

- 每台机器各自部署三件套：**Bun + 桥接目录 + Figma 插件（导入 manifest）**。
- 中继是**本机服务**（localhost:3055），每人跑自己的，互不干扰、无需局域网。
- 建议分发的材料：
  - 本手册（全流程）
  - `使用说明.txt`（简明版）
  - 桥接目录压缩包（含 repo + 启动脚本）
  - 示例导出图（万用表改前/改后对照）
- 学生常见问题预判：
  - "Connected 了但 AI 说连不上" → 面板是不是关了？中继是不是没启动？
  - "频道号在哪？" → 插件面板那一行 `Connected to server in channel: xxxxxxxx`
  - "怎么让 AI 改颜色？" → 直接说"把某某改成某某色"就行
